# 一次 智能体前端 部署踩坑全记录


<p style="text-indent: 2em">之前我用Trae搭完了整套UE UI Profile，当时还觉得免费方案用着也挺顺手，没料到后面会踩这么大一个坑。</p>
<br>


愚人节那天，我准备正式部署上线，结果刚跑起来就卡壳了——其中一个`index`页面一直卡在**挂载状态**，死活加载不出来。

<br>

最开始我怀疑是图标出了问题，还让Cursor帮我删掉了一个可疑图标。因为项目里用到了**代理转发**（其实没什么安全考量，单纯为了匹配域名，跑的是自己部署的JS），Cursor就带着我在路径配置里反复绕圈。

比如把：
`href="/assets/index-BMfGevR0.css"`
改成：
`href="./assets/index-BMfGevR0.css"`

改来改去，问题一点没解决。

<br>

后来我才注意到，项目里**单个JS文件体积超大**，尤其是`index`文件，直接超过4MB。每次Build都要等1分30秒以上，就算换了构建方式、做了各种代码切割，打包速度依然慢得离谱，页面挂载卡死的问题也没改善。

<br>

没办法，只能硬着头皮重构项目，疯狂删减依赖，可还是没用。我又绕回最初的猜测：**还是图标问题**。

<br>

一查才发现，项目里居然藏着一个**4MB的SVG**——这是之前用图片转SVG生成的。最后试了下带AI增强的图片转SVG网站，压缩效果立竿见影，体积直接砍到正常范围。

<br>

改完这个巨型SVG，部署瞬间顺畅，`index`挂载卡死的问题彻底解决。

整个排查+解决过程，前前后后花了**6.46小时**，全程被带着绕弯路，体验极差。

### 后记


再后来，虽然可以加载了，但始终还是很慢，有时加载需耗费长达一分钟以上

<br>

原因是加载了很多依赖，特别是关于markdown解析相关，代码高亮相关的(后移除)，若自行做几个根据markdown的前端解析逻辑，则不会如此阻塞。

<br>

最终采取按需加载依赖并在打包时进行代码分割，缓解了这一问题

<br>

但最坏情况可能要15秒左右，若访问 Ueui-AI 或 矿兵AI 一段时间内没反映，是正常现象
